## 四、调研结论（2026-09-12，网络调研）

### 4.1 识别模型选档 —— 现状最大问题：我们用的 tiny 档精度不足

RapidOCR 官方博客（2026-06）CPU 实测（ExactMatch / 耗时秒）：

| 模型 | 框架 | ExactMatch | CharMatch | 耗时(s) |
|---|---|---|---|---|
| PP-OCRv6_medium | RapidOCR+ONNX | **0.8613** | 0.9491 | 0.0515 |
| PP-OCRv6_small | RapidOCR+ONNX | 0.8419 | 0.9515 | 0.0143 |
| PP-OCRv6_tiny | RapidOCR+ONNX | 0.6968 | 0.8897 | 0.0030 |
| PP-OCRv5_server | RapidOCR+ONNX | 0.8129 | 0.9431 | 0.0655 |

- **我们 PP-StructureV3 管线当前配的是 v6_tiny det/rec**（layout_worker.py 默认值）——精度垫底。
- v6_medium 以 73M 体积超越 v5_server（精度 +5.1%、检测 +4.6%），单模型统一支持中英日等 50 语言。
- 52pojie 帖的「PaddleOCR-V6-Portable」即此路线（PP-OCRv6_medium ONNX + 网页界面 + xlsx 导出），闭源，
  但证明 PP-OCRv6 ONNX CPU 推理做离线截图 OCR 完全可行。

### 4.2 排版还原 —— 两条候选路线

| 路线 | 组成 | 优势 | 代价 |
|---|---|---|---|
| **A. rapid-doc**（RapidAI） | MinerU 精简管线：PP-DocLayoutV3（自带阅读顺序）+ PP-OCRv6-small + PP-FormulaNet + 表格模型，全 ONNX CPU | OmniDocBench 90.157（超 MinerU-Pipeline 86.47 / Marker 78.44）；输出 Markdown/JSON/HTML；`pip install rapid-doc[cpu]` | 模型多、首次下载大；截图（非文档）场景可能过重 |
| **B. RapidOCR + 排序算法** | RapidOCR(PP-OCRv6) 文本块 + PP-DocLayout 版面分类 + GapTree/xy-cut 阅读 order 排序 | 轻量、可控；GapTree 为 Umi-OCR 作者开源纯算法（多栏报刊式排版强项） | 排序/结构化需自己拼装 |

- 现有 PP-StructureV3（paddle 全家桶）已知问题：CPU 内存泄漏/占用过大（PaddleOCR issue #15738）、
  整线多模型导致 CPU 极慢——这就是此前"没成功过"的原因，**方向应换成 ONNX 轻量栈**。
- 截图场景与 PDF 文档场景不同：截图多是 UI 界面（多栏卡片/侧栏/图标），PP-DocLayout 系列按文档训练，
  UI 截图效果需实测；GapTree 对 UI 多栏卡片可能更贴。

### 4.3 图标识别/过滤 —— 业界三层方案

1. **识别前**：忽略区域（Umi-OCR 方案）——适合用户手动排除水印/按钮，不适合全自动；
2. **识别中**：版面模型分类过滤——PP-DocLayout 系列原生输出 figure/icon 等元素标签，
   图标区域直接排除或占位（推荐，随 §3.2 顺带落地）；
3. **识别后**：置信度阈值 + 启发式（宽高比、笔画密度）+ 规则过滤。
- 参考：Umi-OCR 忽略区域、GapTree_Sort_Algorithm、PP-DocLayoutV2 阅读顺序解码（win-accumulation）。

### 4.4 本机实测数据（2026-09-12，venv_ocr + rapidocr 3.9.2，真实截图帧 1526×672 等 3 张）

| 配置 | warm 耗时/张 | 识别质量 |
|---|---|---|
| PP-OCRv6 small（默认，cls 关） | **~1.58s** | 好：终端命令、长段落、中英混排均准确 |
| PP-OCRv6 small（默认配置） | ~1.75s | 同上 |
| PP-OCRv6 medium | 12.8~19.1s | 仅多空格级优化，速度不可接受，弃用 |
| （对照）现管线用的 v6_tiny | 官方数据 ExactMatch 0.697 | 精度垫底，确认弃用 |

- 结论：**PP-OCRv6 small 是本机 CPU 的正确选档**；模型随 whl 内置（29.5MB），无 paddle 依赖。
- 路线 B 拼装验证（`OCR/test_layout_b.py`）：RapidOCR 文本框 + 既有 `_group_paragraphs`
  → 文本页段落分组效果好（阅读顺序正确、续行正确合并）；
  UI 截图中按钮/图标文字成为独立噪音段落 → 引出 §3.3 图标过滤项。
- 验证脚本：`OCR/test_rapidocr_v6.py`、`OCR/test_rapidocr_bench.py`、`OCR/test_layout_b.py`。
