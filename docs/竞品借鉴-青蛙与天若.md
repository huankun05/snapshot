## 二、青蛙截图OCR 画像 ——「系统能力极限主义」

708KB 实现截图+标注+OCR+翻译+长截图+录屏，秘密是**零第三方依赖、全部系统能力**：

| 板块 | 实现路径（实锤） |
|---|---|
| 截图捕获 | 纯 GDI `CopyFromScreen`/`BitBlt`，manifest **PerMonitorV2**；**无 UIA/无智能选区**（纯框选+放大镜+上次选区记忆） |
| OCR① | **`Windows.Media.Ocr`**（WinRT 系统 OCR，离线零依赖）+ 灰度预处理双通道取优（`PreprocessGrayscale`） |
| OCR② | **微信 OCR 侧车**：借用已装微信的 `WeChatOCR.exe` + `mmmmojo_64.dll` IPC（SelfTest/Start/Kill 生命周期，检测 64 位进程） |
| 翻译 | 3 个免 key 端点：Google gtx、**Edge 免费 API**（auth→cognitive）、MyMemory；译文按原文位置覆盖 |
| 长截图 | 手动滚轮定步长 + **边缘分数重叠匹配**（EdgeScore/_prevEdge），重叠认不出→整段跳过提示、绝不拼错 |
| 录屏 | **Media Foundation H.264 sink writer**（30/60fps + 麦/系统声双音轨，零三方编码器） |
| 表格 | 行列坐标聚类 → TSV/CSV |
| 其它 | 低级键盘钩子抢 PrintScreen、`Global\Capture.*` 单实例事件、贴图 Ctrl+滚轮透明度、序号自动递增+说明气泡 |

**战略提示**：与 F2 Tauri 减肥方向同路——把 WinRT/MF/GDI 系统能力用足，体积可以压到极小。

## 四、借鉴决策与实施记录（7 项已落地）

> 全部实现于 **F2 Tauri 版**；标注（F1F2）的渲染端改动走 capture.js/pin.js 双份同步
> （check-render-sync 全绿）。测试底座：cargo test 13 项 + `PETALSNAP_IPC_SELFTEST=1`

### 4.1 ✅ P1-1 Windows.Media.Ocr 兜底识别引擎（青蛙主引擎）

- **落点改为 F2 Rust 宿主**而非 Python 侧车：winsdk 无 py3.13 wheel，且**兜底必须住在服务外**——服务内部兜底救不了「服务本身死了」
- `main.rs wmocr_png()`：windows crate（Media_Ocr 等 feature），18766 不可用/报错/空结果 → 宿主内 WinRT OCR（离线零模型零 GPU；语言包缺失时报错引导安装）
- 附赠 **CJK 逐字空格除噪**（Windows OCR 输出「深 度 学 习」→「深度学习」，`collapse_cjk_spaces`）
- 依赖系统「中文 OCR 语言包」（本机 zh-Hans-CN 已装）

### 4.2 ✅ P1-2 免 key 翻译链 Edge → MyMemory（青蛙三通道）

- 官方端点：`edge.microsoft.com/translate/auth` 换 token（缓存 8min，401 自动刷新重试）→ `api-edge.cognitive.microsofttranslator.com`；MyMemory 按文字脚本猜源语言（无 auto）
- **实测修正（重要）**：本机网络 **Edge auth 恒 404**（geo/策略）、Google gtx 超时（被墙）——**MyMemory 是本机唯一实测可用**通道。链路设计 Edge 优先（可用网络质量好）→ MyMemory 保底，本机实测落到 MyMemory 成功
- 翻译降级 = 兜底 OCR 文本 + 免 key 翻译，面板纯文本模式（translatedImage 留空，渲染端已支持）
- 顺带：reqwest 加 **rustls-tls**（原 default-features=false 无 TLS，127.0.0.1 之外连不出去——F2 首次具备外网 HTTPS 能力）

### 4.3 ✅ P1-3 问 AI 移植到 F2 + 提示词模板模式（天若 OCRModes 思路）

- `capture-ask-ai` 从 notPorted 变为全实现（reqwest 直连用户自配置 OpenAI 兼容接口，错误口径对齐 F1 askAiService；system 消息/temperature 随模板注入）
- 模板清单 `resources/ask-ai-modes.json`（6 模板可编辑），经新 IPC 通道 `ask-ai-modes` 下发，OCR ▾「问 AI」弹模板子菜单（首项自由提问走原输入条，模板一键发）
- 凭据**只读继承 F1 store**（%APPDATA%\petalsnap\eIsland_store，迁移方案 §4.3 互通方向）
- F1 同步获得模板能力（askAiService 加 opts，capture.ts 注册 ask-ai-modes）；双份同步保持
- E2E 现状：mock 端点往返 ✅；未配置路径干净报错 ✅（用户尚未配置真实凭据）

### 4.4 ✅ P2-6 序号自动递增 + 说明气泡标注（青蛙标注件）

- 入口：图形二级菜单新两项（capture.html + SEQ/BUBBLE svg，双份同步）
- **序号（seq）**：拖拽画徽章（内切圆）/单击直放默认尺寸；编号会话内自动递增（撤销不回退、会话重置归零）；白字彩底+白描边
- **气泡（bubble）**：按下点=尾针锚点，拖出泡体（**拖距前 1/4 留给尾针**，几何精确可测）；白底彩框圆角泡+三角尾针（根点=泡体边缘最近点）；画完自动弹轻量 textarea（Enter/失焦提交、Esc 取消），双击重开编辑；**移动=整体平移（含尾锚）、缩放=尾锚不动（保持指向原内容）**
- 两者都是普通 pending 形状——8 向手柄/改色/延迟烘焙/一步撤销全复用现有基础设施；`cloneAnnots` 扩展 n/tail/text 字段防撤销丢数据
- 测试：SELFTEST2 9/9（合成事件走真实手势链：seq-drag/seq-click/bubble-drag 尾锚几何/编辑器/文字提交/render 冒烟/pending 丢弃/lastsel-restore）+ 文字工具自测回归 18 PASS/0 FAIL

### 4.5 ✅ P3-7 贴图 Ctrl+滚轮透明度 / P3-8 上次选区记忆

- **透明度**（pin.js）：上滚更实/下滚更透（6%/格，15%~100%），只作用于图片本体；按 pin 记忆（localStorage），重开自动恢复；flashHint 显示百分比。pin 窗本就 transparent（F1/F2 同），纯渲染端改动
- **上次选区**（capture.js）：确认截图时选区+虚拟屏 W/H 写 store（`petalsnap-last-selection`）；下次截图未动手时自动恢复为初始选区；布局变了记忆作废；store:read/write IPC 双端同一通道

### 4.6 ✅★ P2-4 微信 OCR 兜底 —— 结论反转全过程（最曲折的一项）

**两次结论的演化（如实留档）**：

1. **初判不可行（2026-11-20 上午）**：本机微信 4.2.0.13（Weixin）架构实锤——OCR 是**进程内插件**（`%APPDATA%\Tencent\xwechat\XPlugin\Plugins\WeChatOcr\8096\extracted\wxocr.dll` 24MB，由微信主程序 UniWeChatWin 加载，file_component.xml 的 appClientId 过滤），**青蛙依赖的 WeChatOCR.exe 独立侧车在 4.x 不存在**；`mmmmojo_64.dll` 26 个导出虽在但无可 spawn 的子进程。当时结论：青蛙式只适用微信 3.x，此项放弃。
2. **用户要求上网搜索 → 翻案**：调研发现 **MaaXYZ/WeChatOCR-SDK**（C ABI `wco_*` 接口）已把微信 3.x/**4.x** 的 OCR 调用链完整封装（自有 worker 进程 + mojo 通信 + **自动发现本机微信 runtime**），官方实测版本 = 本机的 OCR 插件 8096。同类实现：swigger/wcocr（C++）、Umi-OCR 微信插件（自带 3.x 文件免装微信）、Python ctypes 教程。
3. **落地**：官方 smoke 3/3 通过（`protocol=4`，热调用 p50 ≈ **211ms**，快于 rapidocr 1.5s 一个量级）→ F2 Rust `libloading` 集成 `wxocr_png()`（PNG→BGRA 内存直喂免落盘、引擎进程内复用、退出 `wco_destroy` 回收）→ **兜底链升级：18766 → wxocr → wmocr**（翻译兜底文本源同步，engine 标签 `wxocr+edge/mymemory`）。

**踩坑（通用纪律）**：C 侧 `WcoImageView` 带保留字段，Rust `size_of` 手填 struct_size 偏小 → `wco_recognize` 恒 status=1 invalid（靠 `wco_engine_get_runtime` + view 字段诊断定位）——**C ABI 结构体一律用 SDK 的 `*_init` 函数填充，不要手填**。

**合规**：SDK = **AGPLv3**（传染性），二进制放**仓库外** `OCR/wxocr-sdk/`（不入 git、不随应用分发，README 记来源/SHA256/查找顺序：`PETALSNAP_WXOCR_SDK` env → 逐级向上）；腾讯 runtime 来自本机已装微信。待办：`_sweep_orphans.ps1` 可补 `wechatocr-worker` 名单（强杀场景 worker 孤儿风险）。
