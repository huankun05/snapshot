# 长截图（滚动拼接）功能问题排查记录

> 记录 Xiyue 长截图功能在 2026-09-07 ~ 09-09 调试过程中遇到的问题、根因与修复。
> 范围：渲染端 `resources/capture.js` + `resources/capture.css`、主进程自动滚动 IPC、编辑器窗口渲染。
> 关联文档：`docs/汐月Electron版现状.md`
> 版本标记：r19 ~ r60（一轮修复记一个 r 号，便于回溯）。

## 一、功能现状

长截图采用「主屏可见 + 自动匀速滚动 + 静止抓帧 + 帧-累积匹配 + DP 最小能量缝拼接」的桌面主流方案
（与 ShareX / eSearch 同源，非录屏式）。数据流：

```
主进程捕获（koffi GDI BitBlt+GetDIBits）
  → 渲染端 lsMatchScroll 帧-accum 匹配
  → lsAppendRows 整数 1:1 拼装 + DP 最小能量缝
  → 编辑器预览 → cropLongShotFull 1:1 导出 PNG
```

截至 r38，三类最显眼症状（画质模糊 / 接缝横线 / 蓝色边框残留）代码层均已修复；
拼接几何在 r26 高选区与 dwarf 矮选区真实帧 E2E 上总高精确命中。r38 之后尚未经用户实测闭环。

**r49 现状更新（2026-09-09）**：滚轮注入已从方案A（mouse_event 依赖鼠标在选区洞内透传）升级为
方案B（PostMessage WM_MOUSEWHEEL 直达选区下方 Chromium 的 `Chrome_RenderWidgetHostHWND` 子窗口）——
彻底修好「鼠标移出选区不滚 / 抢鼠标」焦点依赖，并修复 DPI 逻辑坐标→物理坐标换算 bug。
但用户实测复发两大症状：**① 长图里「大部分内容重复」；② 清晰度仍不行（局部发虚/重影）**。
两者同源——滚轮推进节奏与「静止抓帧」脱节（详见 3.7 节）。

## 三、详细排查

### 3.1 画质模糊（问题 #1）

**现象**：用户多次截图反馈长截图编辑器内整图发虚，但导出 PNG 本身是清晰的。

**根因（r27 实锤）**：用 CDP `Page.captureScreenshot` 抓取编辑器窗口合成输出，与源图逐像素对比（mse=0 判 1:1）。
- 若编辑态发生 setBounds 缩放（如 1708×920 → 946×920），渲染输出 lap_var 永久掉到原图 31%；
- 软件合成（--disable-gpu / SwiftShader）下 resize 后栅格尺度停留 1.0、再放大输出 → 整窗发虚。
- 用户自 r22 编辑器存在以来看到的「模糊」全部是这个，导出 PNG 实际清晰。

**附带澄清**：此前「运动模糊」「遮罩压暗」等理论在真实帧上被证伪（同内容配对误差极低、帧间对齐整数精确）；
顶部「横线/半透明带」是聊天窗 SVG 卡片自身渐变设计，非拼接瑕疵。

**修复**：
- r27：尺寸已满足 → move-only 保持原尺寸；需缩放 → 屏外改尺寸 200ms 后挪回；闭环自愈（主进程 900ms 后实测 lap_var 比值 <0.7 → hide/show 重建合成表面）。
- r28：sharp-guard 守卫固定取图顶部居中，聊天窗顶部纯背景 lap=0 导致守卫整体跳过 → 改为扫描 5×N 候选取 lap 最大区。

### 3.7 r49 复测复发：大部分内容重复 + 清晰度仍差（问题 #7）

**现象（用户实测 2026-09-09 13:46 / 13:48 复现，本轮代码是 r49 方案B PostMessage 滚轮）**：
长截图结果里「大部分内容是重复的」，且局部发虚 / 重影。不是偶发——采集到两段真实会话 manifest。

**取证（本机 `%LOCALAPPDATA%\Temp\xiyue-ls-debug\`）**：

```
会话A  selX427 selY288 selW854 selH336 dpr1.5  → 物理帧高 = 336×1.5 = 504
  frames=9，matches=[{2,s:120},{3,s:250},{4,s:250.01},{5,s:250},{8,s:290},{9,s:258.15}]
  → 首格(s:120) 重叠 = (504-120)/504 = 76%；稳态 ~250 → 重叠 ~50%
会话B  selX596 selY284 selW802 selH400 dpr1.5  → 物理帧高 = 400×1.5 = 600
  frames=5，matches=[{2,s:120},{3,s:420.01},{4,s:433}]
  → 首格(s:120) 重叠 = (600-120)/600 = 80%；随后 s 跳到 420~433（重叠仅 30%）→ 位移跳变 3.5×
```

**根因分析（两条链，同源于「滚轮推进 ≠ 静止抓帧」）**：

**(A) 「大部分重复」= 实际滚动位移过小（重叠远超设计）**
- 设计目标 `lsAutoTargetFrac = 0.5`（`capture.js` L4382）→ 每格期望推 50% 新内容、重叠 50%。
- 实测首格位移仅 **120px**，而帧高 500~600px → **重叠 76~80%**，每帧只引入 20~24% 新内容——
  「几乎整屏被前一帧覆盖」就是用户看到的"大部分重复"。
- 位移不稳定（会话B：120→420→433 跳变 3.5×；frames 数 > matches 数 = 有被拒帧）→ 推进断档 / 忽快忽慢。
- 为何？方案B 的 `delta` 经 Chromium **平滑滚动（Smooth Scroll）异步推进**：delta 被平滑系数放大带惯性、
  且滚动是异步落定的。`lsWaitQuiet`（每 100ms 抓 GDI 灰度、连续 3 次 diff≤0.05 判静止 + 60ms）在平滑滚动
  末段（亚像素缓动、或内容相似度高如纯背景/小字渐隐时）误判"已静止"→ 抓帧时机漂移 → 单帧实际位移
  不可预测（120~433 随机）。位移小 → 重叠大 → 内容重复囤积。

**(B) 「清晰度不行」= 软帧混入拼接**
- 证据：`ls_1788932930521_1/2/3_acc_soft_frame.png` 落盘 → 这些帧 `lap < lsSharpBase×0.6` 且 retries≥3，被标记为软帧。
- 关键缺陷（`capture.js` L4950）：软帧判定后**仅 `lsDebugDump(...,'soft_frame')` 落盘做诊断，并不丢弃 / 重抓**，
  软帧照样进 `lsAppendRows` 拼接 → 滚动动画中途帧 = 上下半透明重影 → 局部发虚。
- 平滑滚动时 GDI 抓到的"静止"在亚像素层仍缓动，sharp-gate 对"下一行文字正在淡入"的帧误判为清晰。

**结论**：r49 已把「鼠标位置 / 焦点依赖」彻底修好（post-wheel 全部 ok=1、全程无需抢前台焦点），
但核心矛盾转向「**滚轮推进节奏 ⇄ 静止抓帧时机** 的脱节」——这是两症状共同的根。位移漂移既是"重复"的因，
也放大了软帧概率。

**修复方向（未实施，建议下一步）**：
1. **首格大步长校准**：首格用固定大步（如 delta=-180~-240 甩出近半屏）先测 ratio，再进稳态，
   从源头规避首格 s=120 的 76~80% 重叠囤积。
2. **静止判定收紧**：`lsWaitQuiet` 的 GDI diff 阈值 0.05 下调至 ~0.02，或连续判 3~4 次 + 额外 settle 30~60ms；
   对 Chromium 平滑滚动尤其关键。
3. **软帧改丢弃重抓**：soft_frame 判定后整帧丢弃并补发一次滚轮重抓（代价仅多一步），杜绝软帧混入——而非仅落盘。
4. **位移多态仲裁**：normal(≈120) 与 best-guess(≈420) 交替时，信任速度先验锁定单一基线，防首格小位移污染后续。
5. **目标重叠下探备选**：位移稳定后可把 `lsAutoTargetFrac` 0.5 → 0.65~0.7（target=0.3~0.4×帧高），提高每帧新内容占比，进一步减少重复观感。

### 3.8 r50 退化与 r50b 回退（2026-09-09 15:21）——对 #7 的认知修正

**现象（r50 首测，会话 `ls_1788938457044`）**：`frames:1`、`matches:[{i:1,t:9712,s:552}]`、4 张 soft_frame 落盘。

**根因（r50 自身两处破坏性改动 + 一个认知错误）**：
1. 静止判定过紧（0.02 / 连续4次 / settle100ms）：含轻微持续动画的页面几乎永不判静止 → 每步吃满 2500ms 超时 → 极慢。
2. soft_frame 丢弃重抓：sharp-gate（lap_var<0.6×EMA）在本内容上**误触发**（正常静帧被判软），丢弃后循环再注入一次滚轮

3. **认知错误**：soft_frame 未必是动画伪影。sharp-gate 的 lap_var 判据把「真实内容就是发虚（显示缩放）」当成本可修复的
   采集抖动 → 不该丢弃。r49 时代「仅落盘、照常拼接」反而正确保真。

**r50b 修复**：回退静止判定（0.05/连续3/settle60）、回退 soft_frame（仅落盘、照常拼接），保留自适应 delta clamp。

**对 #7 的再定位**：内容重复与发虚的根源不是"静止判定不够严"，而是**平滑滚动的位移时机不稳定**。
推进方向应从「收紧静止判定(牺牲速度)」改为「**用匹配器实测位移 s 做稳定步长反馈**」——即让每次注入的滚轮量
根据上一格实测位移修正，使每格位移恒定逼近 0.5×帧高（r50 已保留 clamp 的雏形，仍需按步长=目标直接收敛，而非比例微调）。
