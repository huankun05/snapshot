# 设置页「保存」分组方案（通用页收纳 + 设置备份）

> 2026-11-22 · 状态：**已实施（2026-11-22 ~ 11-24），待用户实测**
> 背景用户诉求：所有"东西存在哪里"统一收进「通用」页；设置要能备份；描述精简。

## 〇、实施与本文方案的差异（2026-11-24 收口时补记）

- **形态改为「单卡折叠版」而非 5 张独立卡**：`saveCard` 一张卡内含 4 行目录（截图/录屏/下载资源/设置备份）
  + 一组按钮作用于选中行（更改/恢复默认/打开目录），有自定义项时自动展开，摘要徽标显示「n 项自定义」。
  数据位置一览不再单独成卡，由每行「打开目录」承担。
- **录屏目录键为 `screenshot.rec-save-dir`**，录屏页保留「保存方式/文件名前缀」等录屏专属项，目录本身只在通用页一处。
- **备份多了「最近备份」列表 + 一键恢复**（`settings:backup-list` / `settings:backup-restore`），
  恢复与导入同为整体替换语义，均先自动写 `settings-*-pre-import.json` 可回退。
- **操作反馈统一为 `notify()` 浮层**（成功绿✓ 2.5s / 失败红✗ 4.5s，锚定按钮），取代原先复用 `showInfoToast` 的写法。
- 三个决策点落地：①录屏页不留目录快捷入口（每行已有「打开」）；②自动备份未做，列二期；③导入=整体替换+导入前备份。
- **同期还有两块不在本文范围的改动**：识别页「引擎优先级链」编辑器（`screenshot-ocr-engine-chain`，
  云端只许排首位）与「可选资产手动下载」（表格/版面模型、Tesseract 语言包，服务端缺模型报 `modelMissing`，不再静默联网）。

### 收口审查修掉的 3 个缺陷（2026-11-24）

1. **F1 漏注册 `settings:backup-list` / `settings:backup-restore`**（服务函数已存在），F1 备份列表恒「读取失败」→ 已在 `app/main.ts` 补注册。
2. **F2 `settings:backup-restore` 参数形态错误**：渲染端传位置字符串，Rust 却按 `a0.get("name")` 取 → 恒「非法备份文件名」，一键恢复在 F2 必败 → 改为兼容字符串/对象两形态。
3. **F2 `ocr:model-download` 同型错误**（`a0.get("id")`）→ 恒「未知模型 id」，F2 模型下载必败 → 同上修复。
   另：`ocr-service/rapidocr_service.py` 副本自 2026-09-17 起未随根目录更新（差 756 行），本次已同步（SHA256 一致）。

## 二、目标形态：「通用」页 → 「保存」分组

通用页新增分组（位于现有通用项之后），5 张卡自上而下：

### 1. 截图保存目录（新增配置）
- store 键：`screenshot-save-dir`，空 = 系统「图片」
- 行为：**保存文件**对话框的默认路径改用它；**长截图拆分**直接写入该目录（替代写死的 Pictures）
- 控件：目录选择「更改…」+「恢复默认」+ 当前路径显示（同识别页"存放位置"行样式）
- 悬停补充：仅作用于「保存」；复制到剪贴板与贴图不落盘

### 2. 录屏保存目录（迁移）
- 现有 `recFolder` 原样迁入；录屏页删除该行（避免两处入口）
- 悬停补充：仅「固定文件夹」模式生效

### 3. 下载资源目录（迁移）
- 现有 `screenshot-assets-dir` 原样迁入（含"更改后重启识别服务生效"逻辑）
- 识别页资源卡删除"存放位置"行，卡片保持模型状态 + 下载按钮

### 4. 设置备份（新增）
- store 键：`settings-backup-dir`，空 = `文档\petalsnap-backup`
- 三个动作按钮：
  - **立即备份**：把 eIsland_store 全部 JSON 打包成单文件 `settings-YYYYMMDD-HHmmss.json` 写入备份目录，保留最近 10 份（滚动清理）
  - **导出设置**：另存对话框（可存 U 盘等任意位置），跨机器迁移用
  - **导入设置**：选文件 → 校验（JSON + 键名白名单外直接拒）→ 合并写回 → 提示重启应用生效
- 悬停补充：备份内容=快捷键/识别引擎优先级/翻译/各页偏好；不含账号凭据

### 5. 数据位置一览（只读 + 打开按钮）
- 设置数据：`…\eIsland_store`「打开」
- 日志目录：「打开」（F1/F2 各自解析，沿用现有 openPath）
- 不提供修改这些位置的入口（收益低、风险高）

## 三、实现涉及面（预估一轮 + 半轮）

| 层 | 改动 |
|---|---|
| storeKeys | +`screenshot-save-dir`、+`settings-backup-dir` |
| capture.ts | 保存对话框 defaultPath 读配置；长截图拆分目录读配置 |
| settings.js（双份） | 通用页新分组 5 卡；录屏页删 recFolder；识别资源卡删存放位置行；备份按钮逻辑 |
| IPC（双壳） | `settings:backup-now` / `settings:export` / `settings:import`（F2 Rust 端打包 zip 或平铺 JSON；F1 Electron 同语义） |
| main.rs | openPath 的 `screenshots` 目标从 %TEMP% 改为配置目录（顺手修掉临时目录怪相） |
| 构建 | esbuild + cargo（F2 前端资产必须重编译才生效） |

## 四、待确认的 3 个决策点

1. **录屏保存目录**：迁到通用页后，录屏页要不要留一个"打开目录"快捷入口？（建议留，不占地方）
2. **自动备份**：MVP 先做手动三按钮；自动备份（每次设置变更防抖 30s / 每日一次）列为二期，要不要这轮就带上？
3. **导入语义**：覆盖合并（新键写入、旧键保留）还是整体替换（清空后写入）？（建议整体替换 + 导入前自动做一次"导入前备份"，可一键回退）
