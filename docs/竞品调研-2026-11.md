## 二、我们的位置：不追形态，追「识别之后」

PixPin 已把**截图形态**做满（多区域/自由/折线/多窗口、窗口贴图、聚光灯、圆角阴影、打印、工具栏自定义）。
逐项追平没有意义——我们的差异化是另外四条，且都比它深：

1. **UIA + 像素双链智能选框**（窗口级预览 + 相对深度下钻 + 像素收边），PixPin 只有 UI 检测一档；
2. **本地识别引擎链 + 用户可排优先级**（18766 RapidOCR → wxocr → wmocr，云端只许显式排首位）；
3. **本地 Hy-MT2 翻译擦写回填 + 免 key 兜底链**；
4. **问 AI 模板**（`ask-ai-modes.json` 可编辑，system prompt / temperature 随模板注入）。

⇒ 战略：**截图形态只补「没有就断链」的缺口（长截图、录屏、CF_HTML），增量投在「识别之后能干什么」。**

## 五、不借清单（含理由，防重复调研）

- **Quick Access Overlay（截后浮层）**：与「移除全部确认弹窗、静默流程」的既定 UX 冲突；若做必须默认关。
- **多区域/自由/折线/多窗口截图、工具栏按钮自定义**：投入大，收益已被智能选框覆盖大半。
- **上传图床 / 云同步 / 账号体系**：与本地优先战略冲突，凭据维护面爆炸（同天若全家桶结论）。
- **macOS / Linux 版**：主线是 Windows + WebView2，跨平台另立项。
- **再换 OCR 模型或接云端引擎全家桶**：引擎链已够，问题在结果的后处理而非识别率。
- **本地公式识别模型**：先用 N5 模板验证频率再定。
