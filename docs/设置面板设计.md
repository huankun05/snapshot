## 一、现有配置底账（设计的落脚点）

设置面板一半的工作是给**已存在但没有 UI** 的 store 键做界面（数据在
`%APPDATA%\eisland-screenshot\eIsland_store\*.json`，读写 IPC `store:read/write` 已就绪）：

| store 键 | 现状 | 面板归属 |
|---|---|---|
| `screenshot-hotkey` | 热键，主进程启动时注册（有备用键链） | §截图 |
| `screenshot-engine` | `plugin`/`js` 抓帧引擎偏好 | §截图（高级） |
| `screenshot-ocr-engine` | `local`(Tesseract)/`paddleocr`(实际已路由到 RapidOCR 服务)/`server` | §识别 |
| `screenshot-translate-engine` | `local`(Hy-MT2 端侧)/`cloud`(百度)/`server` | §翻译 |
| `screenshot-cloud-translate-appid/secretkey` | 云翻译凭据，空则回落本地 | §翻译 |
| `screenshot-translate-target-lang` + `screenshot-text-translate-target-lang` | 目标语言，capture.js 双写 | §翻译（沿用双写） |
| `screenshot-translate-source-lang` | 源语言 | §翻译 |
| `i18n-language` | capture 界面语言（zh/en 内联字典） | §通用 |
| （无键）开机自启 | 未实现，用 Electron `app.setLoginItemSettings` 即可，无需 store | §通用 |
| （无键）OCR 内存策略 | 独立应用现固定"启动预热"（main.ts 600ms 拉起）；三档是 §3.6 规划项 | §识别（依赖开发） |

## 二、窗口与信息架构

### 2.1 窗口
- 标题：**「拾花 设置」**（产品名已定「拾花 PetalSnap」，见 `UI设计方案.md` §一）
- 尺寸 880×640（最小 760×560，可调），普通 BrowserWindow，可与截图窗共存；单例
- 入口：托盘菜单**「设置…」**（v1）；截图面板标题栏加 ⚙ 按钮（二期，capture.js 改动缓行）
- 技术形态：`settings.html` + `settings.js` + `settings.css`，与 capture/pin 同构
  （cwd 资源定位 + 既有 preload/webPreferences 模式），**零新依赖、零框架**

### 2.2 分区（左侧导航，v1 五个 + 二期两个）

| # | 分区名 | 图标（Lucide 名） | 内容 | 版本 |
|---|---|---|---|---|
| 1 | 通用 | `settings` | 界面语言、开机自启 | v1 |
| 2 | 截图 | `crop` | 截图热键、抓帧引擎（高级） | v1 |
| 3 | 识别 | `scan-text` | 识别引擎、性能档位（三档卡片）、默认识别动作、服务状态行 | v1（三档接线依赖开发） |
| 4 | 翻译 | `languages` | 翻译引擎卡片（本地/云 + 凭据）、目标语言 | v1 |
| 5 | 关于 | `info` | 版本、服务版本、日志目录、隐私说明 | v1 |
| 6 | 贴图 | `pin` | 可恢复贴图数等 | 二期（依赖 pin 恢复栈） |
| 7 | 输出 | `download` | 文件名模板、快捷/自动保存 | 二期（见 §7） |

命名说明：OCR 相关分区叫「识别」不叫「AI 能力」——与截图面板既有词汇（OCR ▾ 菜单可保留）
对用户更直白；英文分区名 General / Capture / Recognition / Translation / About。

布局：左导航 190px（图标 18px + 文字 13px，活动项 accent 底色胶囊）+ 右内容区滚动，
卡片宽自适应、间距 12px；分区大标题 19px/700 在内容区顶部。

## 三、逐项设置详表（v1）

文案按 Shotera 三要素写：**行为 / 生效时机 / 副作用**。以下直接是可抄进代码的文案。

### 3.1 通用
| 设置 | 控件 | 默认 | 文案（说明行） | 存储/实现 |

### 3.2 截图
| 设置 | 控件 | 默认 | 文案 | 存储/实现 |
|---|---|---|---|---|
| 截图热键 | 键帽捕获按钮（点击→按下组合键→绿勾；Esc 取消） | Alt+Q | 全局生效。与其他软件冲突时自动换用备用键（Ctrl+Alt+Q 等），以托盘菜单显示为准 | `screenshot-hotkey`；写后主进程即时 `unregister+register`（复用 `registerScreenshotHotkeyIpcHandlers` 通道） |

### 3.3 识别
| 设置 | 控件 | 默认 | 文案 | 存储/实现 |
|---|---|---|---|---|
| 识别引擎 | 单选卡片 ×2 + 下拉兜底：**本地 RapidOCR（推荐）**徽章「内置 · 离线」/ 本地 Tesseract 徽章「兼容」/ 云端 OCR（下拉保留） | RapidOCR | 识别截图中的文字并输出 Markdown。「本地 RapidOCR」精度与速度最佳，全程离线；Tesseract 仅作兼容保留；云端需网络 | `screenshot-ocr-engine`（值映射：UI「RapidOCR」= 现有 `paddleocr`，**不迁移数据**） |
| 识别性能档位 | 单选卡片 ×3（Shotera 模型卡样式）：<br>① **常驻** 徽章「最快」<br>② **截图时预热（推荐）**<br>③ **按需** 徽章「零占用」 | 截图时预热 | 控制本地识别模型何时加载。常驻=启动即加载，识别零等待，约占 420MB 内存；截图时预热=按热键即开始后台加载，框选时间覆盖初始化，点识别已是热态；按需=点「识别」才加载（首次约 4~6 秒），平时零占用 | 新键 `screenshot.ocr-warmup`（`resident`/`capture-prewarm`/`on-demand`）；主进程按档控制 `ensureRapidOcrService` 时机（现固定 resident，**接线为 §3.6 规划项**，UI 先行、灰色角标「即将支持」） |
| 默认识别动作 | 下拉：文字识别 / 表格识别 / 智能识别 | 文字识别 | 点工具栏 OCR 主按钮执行的动作；其余动作仍从 ▾ 菜单进入，切换立即生效 | 新键 `screenshot.ocr-default-action`；capture.js 主按钮点击处读此键分发 |
| 服务状态 | 只读状态行 + 按钮「打开日志」「重启服务」 | — | 显示识别服务运行状态（如：运行中 · GPU(DirectML) · 端口 18766 · v4-align）；识别异常时可在此重启 | 无键；主进程新增 `ocr:health` IPC 透传 `/health` + `ocr:restart` |

| 危险（仅重启服务按钮 hover） | `#D93843` |
| 字体 | `"Segoe UI", "Microsoft YaHei", system-ui, sans-serif`，基准 13px（ Shotera 的界面字号设置暂不做） |

### 4.2 组件规格
- **开关 toggle**：40×22，圆角全弧，关=灰轨白点，开=accent 轨白点，点击即存
- **分段按钮**：灰底 `#ECEEF2` 圆角 6 容器，选中段白底 + accent 文字 + 微阴影（Shotera 同款）
- **下拉**：自定义样式 select（右侧 chevron 图标），宽按内容自适应
- **步进器**：`− 值 +`（贴图恢复数等二期用）
- **键帽（热键）**：`等宽字体`（Consolas），浅蓝底 `#EEF3FF` accent 文字，圆角 6，宽 110px
  居中；点击进入捕获态（文字变「按下组合键…」），设置成功右侧绿勾 ✓，Esc 取消
- **单选卡片**：边框 `#E3E6EB` 圆角 8；选中 accent 边框 + `#F3F7FF` 底 + 左侧 radio 点；
  徽章规格：高 20px 圆角 4 字号 11——「内置/离线」绿底、推荐 accent 底、零占用/兼容 灰底、
  即将支持 黄底
- **服务状态行**：12px 等宽，状态点 8px（绿=运行/红=停止/黄=启动中），右侧两枚次级按钮

## 六、实现方案与工作量

1. `app/settings.ts`（~80 行）：单例 BrowserWindow（880×640，`settings.html`，preload 复用
   capture 窗的），托盘菜单插入「设置…」；新增 IPC：
   `settings:openPath` / `settings:pickFolder` / `settings:setLoginItem` / `settings:getLoginItem` /
   `ocr:health` / `ocr:restart`（均为薄封装）
2. `resources/settings.html + settings.css + settings.js`（~700 行）：静态声明式渲染——
   每个设置项一个数据结构（键/文案/控件类型/选项），js 只负责渲染与绑定，i18n 走内联字典
3. 热键写入：复用 `registerScreenshotHotkeyIpcHandlers` 既有注册通道，主进程收到新值即时重注册
4. **工作量**：v1 壳 + 现有键收编（通用/截图/翻译/关于 + 识别的引擎与默认动作）≈ 1~1.5 天；
   识别性能三档接线（改 main.ts 预热时机 + capture-prewarm 的热键钩子）≈ 0.5~1 天
   （属于功能状态清单 §3.6 的规划项落地）
